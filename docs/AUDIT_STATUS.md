# Production-readiness evidence map

This maps the original performance, release and missing-test findings to the
current implementation. It is not release approval. A source change, a local
test and a hosted/device acceptance result are different kinds of evidence.
Use [release acceptance](RELEASE_ACCEPTANCE.md) for each release candidate;
keep dated local results under `docs/development-sessions`.

## Performance and capacity

| Finding | Implemented control or automated coverage | Remaining acceptance |
|---|---|---|
| 1,000 Windows files | HTTPS harness rejects 1,001 manifest entries and transfers/verifies all 1,000 accepted files | Physical sender/receiver UI run with representative media |
| 10,000+ iOS assets | Bounded visible batches and native preparation reservations; JavaScript regression coverage | Physical PhotoKit memory, cancellation and exact exported bytes |
| 100+ GiB aggregate | Server active-file, declared-byte and free-space admission; failed cleanup retains reservations; native allocation tests | Long device workload and low-storage acceptance |
| Very large individual video | Shared generated byte/chunk policy and client effective-capacity rejection | Largest supported native and compatibility-path device transfers |
| Duplicate-heavy inventory | Stable keyset pages of at most 256, bounded verification cache, streamed directory reconciliation; native and HTTP multi-page tests; 1,000 duplicate decisions alongside 20 uploads with request-latency observations | Representative-library hashing and lock-wait measurements; finalization and reconciliation still serialize expensive work |
| Stress and sustained load | Release concurrency profile with integrity/error/memory gates; separate 15 GiB volume profile; sanitized reports retained locally | At least 60 minutes on physical devices plus LAN/iperf3 comparison |

No loopback result establishes Wi-Fi speed or universal throughput. The volume
profile does not establish hour-long endurance. SQLite remains the inventory
store; bounded pages do not remove filesystem/hash costs or all lock contention.

## Dependencies and release

| Finding | Implementation | Remaining acceptance |
|---|---|---|
| Reproducible onboarding | Prerequisite checker, pinned native restore, `npm ci`, documented verification dispatcher | Fresh Windows VM without the existing developer tool/cache state |
| Exact release-commit tests | Release workflow runs full verification and staged-server integration/stress before artifact upload | Hosted run at the committed candidate |

| Remote policy | Required checks/reviews documented | Repository ruleset/branch protection configuration has not been verified |
| FMT assertions | Global suppression removed after current-baseline Debug probes; formatting regression retained | Continue native build/integration gates when dependency versions change; historical crash cause is not established |

See [dependency advisory rationale](../SECURITY.md#native-dependency-advisory-review)
and [release workflow security](RELEASING.md#workflow-security). Source manifest
versions do not prove the contents of an older distributed installer.

## Missing-test checklist

| Original test request | Current coverage and limits |
|---|---|
| Authorization matrix | Sensitive-route rejection checks for pairing-only, denied/revoked and Windows device credentials; native grant scope and valid flows. Keep route inventory aligned as endpoints are added. |
| Cross-owner cancellation | Isolated same-ID upload owners and cross-transfer grant rejection before mutation |
| Denied/cancelled/expired exhaustion | Bounded session history, capacity/reuse and clock-driven pending/idle/absolute expiry tests |
| Allocation and malformed Base64 | Abandoned uploads, declared-byte/active limits, cleanup failures and malformed first-chunk rejection |
| Storage faults | Test-only mapped-copy, view/file flush, publication/delete faults and failed/truncated hash reads |
| Startup failures | Occupied ports, ownership conflicts, partial startup and orderly bounded shutdown |
| Protocol boundaries | Shared generated limits, client effective capacity, chunk limits and 1,000/1,001 manifest boundaries |
| Temporary recovery | Owned browser/native temporary namespace and unrelated-file preservation; physical interruption remains a device gate |
| PhotoKit | Source-contract/JavaScript tests only; cancellation, low storage, edited/iCloud/large assets and exact resource bytes require iPhone testing |
| Pinned-network cancellation | Real Windows TLS server stalls and trickles responses; real Swift URLSession cancellation remains unverified |
| Installer ownership | Exact executable/PID helper and isolated side-by-side server tests; full simultaneous installations and uninstall require installer acceptance |
| Release-commit acceptance | Workflow compiler/test/staged-server/provenance gates plus manual evidence template; packaged GUI/fresh-install/device acceptance remains required |

All filesystem fixtures use the isolated temporary-root contract. None grants
permission to test against a developer's normal Pictures upload directory.
