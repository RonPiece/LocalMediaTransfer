Overall assessment

The base deserves incremental refinement. The UI, hashing, transport and security already have separate modules. Native controls, modal focus isolation, bounded hashing workers, queue locking, cached progress references and transform-based progress are useful existing choices. No evidence from this audit justifies introducing React, an animation library or a full rewrite.

Evidence limits: inspected source; ran the existing Node tests; reproduced blocked-storage failure in a VM; inspected the real static UI in a loopback fixture at desktop size and 390 x 844. The fixture used synthetic authentication and rejected uploads. It did not test the C++ server, real throughput, device Safari, screen-reader speech or measured main-thread stalls. Playwright Test, axe and dedicated profiling integration are not configured by this review.

Architecture and UX findings

1. High: primary green lacks text contrast

The rendered header and upload button use white over a green gradient. Calculated endpoint contrasts are 2.54:1 and 1.92:1. The subtitle and 14px action text require 4.5:1; even large text requires 3:1. Choose Files also uses this green on a pale surface. Darken semantic action/background tokens or choose a darker foreground; verify every hover/focus/disabled state separately.

style.css:35, 60, 497, 510 / rendered computed styles checked

W3C contrast guidance

2. High: an optional language preference can stop startup

I18n.detectLanguage() reads localStorage without a guard. A SecurityError escapes into the application loading-error path before upload initialization. Language changes also write without a guard. A read-only VM reproduction confirmed the thrown error. Handle unavailable preference storage and continue with navigator language and memory-only preferences.

js/core/i18n.js:18, 65 / js/app.js:74

MDN: storage access may throw SecurityError

3. Medium: noisy live regions

Speed text is updated every 500ms and elapsed time every second inside polite live regions. Those code paths are confirmed; actual spoken behavior depends on assistive technology and remains untested. Keep visual telemetry, and announce phase changes, useful milestones, completion and actionable errors through a dedicated status region.

index.html:82,108 / js/upload/manager.js:525,577

W3C: avoid excessively chatty status updates

4. Performance risk: grouping does not yield the main thread

addFiles() groups files into hundreds and uses fragments, but creates every row synchronously in one call, including rows in collapsed groups. This is not lazy rendering. Content visibility can reduce rendering work but does not avoid constructing those nodes. Profile synthetic selections before choosing incremental construction, lazy group mounting or virtualization. No freeze duration has been measured here.

js/upload/manager.js:394-433 / js/ui/progress.js:36

web.dev: break up long main-thread tasks

5. Medium: compact language menu lacks Escape dismissal

Opening the language dropdown and pressing Escape leaves aria-expanded=true. Reproduced in the browser at 390px. Add predictable dismissal and focus behavior to this disclosure; preserve its native language buttons and selected state.

js/core/i18n.js:98-119

6. Startup needs bounded, explicit states

Twelve scripts are requested sequentially; bootstrap/token verification fetches have no timeout. These are source-observed latency and recovery risks, not measured delays. The failure banner does not explicitly lock controls or provide an accessible retry control. Start disabled, expose initializing/ready/retry states, bound authentication waits, and measure the request waterfall before adjusting script delivery.

Important M1: progress decoration outlives progress

The aggregate fill's pseudo-element always runs an infinite shimmer. Completion updates the bar but does not remove this animation; it ends on reset/hiding or under reduced motion. Tie decoration to actual activity, or remove shimmer entirely. A completed transfer should be visually settled. This finding is based on CSS and completion-path inspection; a real completed upload was not exercised here.
